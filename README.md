# Claude standalone Android wrapper (v3.0.20)

Fresh Android project. Runs `https://claude.ai/` in an in-app Android WebView. Claude itself stays inside the WebView; external authorization links can optionally be opened in the system browser after user confirmation. Requires the OS-provided Android System WebView renderer (part of Android; not bundled into this APK).

- `INTERNET`, **on-demand `RECORD_AUDIO`** for Claude voice dictation, and normal (non-runtime) `MODIFY_AUDIO_SETTINGS` for Chromium's microphone routing. Android asks for mic consent only when `claude.ai` requests audio; non-Claude origins and camera/video requests are denied. No phone/SIM, location, camera, Wi-Fi or storage permission. Rejecting the mic prompt leaves text chat and file upload usable.
- Android back/edge-swipe first goes back in / closes an open external layer; on Claude itself it minimizes the app directly, not browser history. The launcher uses `singleTask`, so reopening an existing app returns to its live WebView without a new `loadUrl`. If Android kills the process under memory pressure, restoring a WebView may require a network load; no app can keep a killed process alive without a persistent service.
- Status/navigation bars follow the page color where it can be read; a light cream fallback is used. Color checks are throttled and skip identical updates to reduce UI work. Refresh rate is left to the system; pinning the window to a display mode is the suspected cause of screen corruption while dragging text-selection handles (when the selection magnifier appears).
- Uses Android's system document picker for file/image uploads, supports multiple files where the website allows it, and handles picker cancellation. Extension-based `accept` lists fall back to showing all files, so accepted files are never greyed out. No storage permission. Downloads (https, `data:` and same-page `blob:` links) are saved only after the user picks a location in Android's "save as" screen (one at a time); no JavaScript bridge is exposed to pages. https downloads follow redirects themselves and send each host only its own cookies, so Claude's session cookie never goes to a redirect target such as a storage CDN.
- Link policy: the main page only ever shows `https://claude.ai` (and `*.claude.ai`). Every other main-frame navigation — including Anthropic and Google links, `target=_blank` links and redirects — is stopped first and asks, over the page the user is on: open in browser, copy link, or open in app. "Open in app" uses a separate layer with a visible host bar (⋮ for browser/copy, Close/back to leave); the Claude page is never navigated away. Approvals are per exact host and per layer, and are forgotten when the layer closes. Inside that layer, links that would open a new window load in the same layer, still behind the same confirmation. If an approved external page leads back to Claude (e.g. a connector authorization callback), the link is handed to the main page. Form POSTs to unapproved sites are blocked before any request is sent, and the Claude page is restored. Non-HTTPS links are not opened and can be copied.
- Popups opened by Claude (e.g. Google sign-in at `accounts.google.com`) stay hidden until their first page is allowed, keeping `window.opener` for the sign-in result; any other popup destination asks first and is discarded if not continued. Google may still return `403 disallowed_useragent` because it rejects embedded WebViews; the app does not spoof its UA.
- Privacy: third-party cookies are disabled, the `X-Requested-With` app-package header is disabled where the WebView supports it, WebView usage metrics upload is opted out, copied links are marked sensitive on Android 13+, and downloads send only the WebView's own cookies for that URL with no Referer. Safe Browsing stays on.
- On Claude's composers (chat's ProseMirror editor and textarea composers such as Claude Code), Enter clicks the single visible, enabled Send/Submit button next to the editor; Shift+Enter remains a line break and Enter that confirms a Chinese/Japanese/Korean IME candidate still only confirms it. If no single send button is found, a Stop button is showing, or the editor is inside a dialog, Enter keeps its normal behavior. The script is registered before Claude's own scripts where the WebView supports document-start scripts, and it does not watch the page for DOM mutations. No behavior is injected on other sites.
- Cookies: first-party cookies and site storage are kept on disk, so logins (Claude, GitHub, etc.) persist across app restarts and are shared between the main page and the external layer. Only third-party (cross-site, embedded) cookies are blocked.
- Light/dark: the app theme follows the system (`values-night`), so the WebView reports the matching `prefers-color-scheme` and Claude renders its own dark theme. Forced/algorithmic darkening of pages (including OEM "dark mode for all apps") is disabled. After switching the system theme while the app is open, swipe the app away and reopen it.
- The soft keyboard does not pop up by itself: Claude's scripted focus of its composer (page load, navigation, returning from the background) is ignored unless the user just touched the composer or its buttons, typed on a hardware keyboard, or the keyboard is already up. The activity also starts with the keyboard hidden.
- Returning from the background: the main WebView ignores "window hidden", so Chromium never marks Claude's page hidden. Otherwise it evicts every rendered tile and Claude refreshes on visibilitychange, and returning waits for a full re-raster. The page is shown immediately instead. Costs: more memory in the background, and Claude's page is not throttled as a hidden page while the process is not frozen (a streaming reply keeps going). Offscreen pre-raster also keeps tiles on background memory trims.
- If the WebView renderer crashes or is killed by the system, the app is not taken down with it: an external layer is closed, and the Claude page is recreated and reopened (a reload is unavoidable then).
- Text selection rendering: dragging selection handles (system magnifier) made some devices composite the page wrongly — large solid backgrounds came out black while the DOM colours were unchanged (confirmed with an on-device diagnostic). While a text-selection toolbar is active, the WebViews render into their own hardware layer; normal rendering resumes when the selection ends.
- Network routing, DNS, IP, time zone and WebView fingerprint are controlled by device/network settings, **not** by this app. No claim of ban prevention.

GitHub Actions tests and builds every push and pull request (pull requests from forks, which get no signing secrets, build an unsigned debug APK for checking only), and publishes a signed release APK for `main` at `v<versionName>` (read from `app/build.gradle`); an existing release is never overwritten, so bump the version to publish. Signing secrets use the same local keystore as the previous installed v2 so upgrades don't require deletion; no old application code, resource, or runtime data is needed. The source is newly written. The signing keystore is stored privately outside the repository.
